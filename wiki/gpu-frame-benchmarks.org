#+title: Hardware GPU frame baselines
#+startup: overview

* Hardware completion timing, not a monitor FPS counter
:PROPERTIES:
:ID: 4C7L3C
:END:

=scripts/bench-gpu-fps.lisp= is the cross-platform fixed-target baseline for
Luvcraft-on-Luft, old Luvcraft, and the actual default Luft atelier. It uses
the real renderers, shader pipelines, scene resources, and queue completion.
It does not use screenshots as a timing mechanism.

Temple's independent M2 Pro / Metal 4 three-resolution measurements are
recorded in #B4E7Z5, including its own source cohorts, AA controls and counter
limitations. Compare like scene cohorts, not a finite island to a live world.

** Reproduce

Run =make= first. On Linux select a hardware Vulkan ICD explicitly: the Nix
environment's default offscreen ICD can otherwise be lavapipe. For chapel:

#+begin_src sh
VK_DRIVER_FILES=/run/opengl-driver/share/vulkan/icd.d/radeon_icd.x86_64.json \
SDL_VIDEODRIVER=offscreen BENCH_FRAMES=600 BENCH_WARMUP=60 BENCH_REPEATS=2 \
BENCH_OUTPUT=build/chapel-gpu.sexp \
./env sbcl --script scripts/bench-gpu-fps.lisp
#+end_src

On macOS omit the two Linux driver variables. =BENCH_SIZES= is a comma-separated
list such as =1280x720,1920x1080,6016x1692=. =BENCH_SCENES= selects any of
=alpine,meadow,cave,balls,turtle,terminal,companion,live-alpine,live-meadow,atelier=.
=BENCH_MSAA= defaults to 4 on Luft; use 1 for an explicitly single-sample
comparison with old Luvcraft. =BENCH_SKY_OFF= and =BENCH_TERRAIN_OFF= are
controlled draw ablations, not optimizations or full-frame FPS claims.
=BENCH_CAPTURE_DIR= saves coverage images outside the measured interval.

** Measurement contract

Each measured frame advances the relevant fixture by a fixed 1/60 second,
encodes into a fixed-size BGRA8 sRGB target, submits, and waits for completion.
CPU frame time includes simulation and command encoding; CPU encode time
excludes simulation. Completion time includes CPU work, submission, GPU
execution and the completion wait. Completion FPS is 1000 divided by mean
completion milliseconds. There is deliberately no CPU/GPU frame overlap.
These are serialized offscreen throughput numbers, not displayed FPS,
input-to-photon latency, or a prediction of an overlapping presentation loop.
Command destruction and timestamp collection are outside completion timing.

Vulkan uses 64-bit GPU timestamps at ALL_COMMANDS around the frame and each
render pass, scaled by the device's timestamp period and valid-bit count.
Repeated pass labels report per-invocation samples: multiply their mean by
sample-count/frame-count before adding them into a frame budget. Metal uses
MTL4 queue submission feedback; it waits for delayed feedback only after
capturing completion time. There is no drawable acquisition in this path,
so no scene/presentation split into separate submissions. Missing GPU samples
fail the run rather than silently biasing the statistics. CPU pass encoding
timings are available on both backends. Percentiles use nearest rank.

TAA and dynamic resolution are OFF. The requested render extent is asserted,
not inferred from window dimensions. Luft's non-temporal default is 4x MSAA;
old Luvcraft is single-sample. Lighting, bevels, atmosphere and finishing are
not visually equivalent implementations. Fixed Luft fixture exposure is
0.45; the actual atelier retains automatic exposure. Old uses its host default.

** Scene coverage and limits

The seven finite fixtures use the same occupied 32x32 cells on both hosts,
with seed 7 for alpine/meadow and corresponding coordinate/camera transforms.
They are small cell-matched islands, not a claim about the game's full
resident world. Cave has a roof, walls and one lantern. Balls keeps 100
physics bodies awake and runs the same solver/terrain on both hosts. Turtle
advances urge, contact, locomotion and carried rider pose. Terminal focuses
the actual PTY-backed panel with 24 deterministic lines. Companion creates an
actual gnome turn and visible thought cloud without a network AI provider.

=live-alpine= and =live-meadow= use actual seed-7 game streaming, settled
before measurement, with fixed corresponding cameras. Luft's nine 64-cell
resident chunks and old Luvcraft's 169 16-cell chunks are different residency
policies, not exact geometry matches. =atelier= invokes =start-viewer= with
the default world, not a flat Luvcraft fixture. No player save is written.
Its default first-person world and closed atelier drawer are retained; this
is not a stress test with all editor panes open. Fresh captures verified the
actual streamed landscape/control and the deterministic terminal fixture.

Coverage captures were inspected. The cave is enclosed on both hosts, but
Luft's lantern appears as a dark orange/bevelled cube without the obvious
warm pool seen under the old bright lamp. Cave timings must not be described
as equal lighting quality. Neither UI text, bevel geometry, exposure, nor
viewmodel details are pixel-identical between renderers.

** Chapel environment

Chapel is Linux 7.2.0, Intel i7-10700K, AMD Radeon RX 6600 XT (NAVI23,
PCI 1002:73ff), amdgpu and RADV Mesa 26.2.0. Vulkan reports a discrete device,
10 ns timestamp period and 64 valid timestamp bits. Software device types
are rejected. The machine has a Wayland socket, but its physical display
connectors are disconnected. SDL's offscreen video driver and the real GPU
are sufficient; there is no monitor presentation measurement here.

Clocks/governors are not pinned: GPU performance level is auto, CPU governor
is powersave. Existing desktop applications and unrelated Lisp images were
left intact. Results describe this machine's ordinary shared session, not
an exclusive clock-locked lab run.

** Frame-pass attribution

The first repetition's Luft alpine 720 GPU budget is 2.76 ms, including
2.55 ms in =luft site streams= and 0.134 ms in HDR presentation. At 1080 the
corresponding means are 5.92, 5.51 and 0.274 ms. Cave's site pass is 10.29 of
10.67 ms at 720 and 15.87 of 16.43 ms at 1080. This pass combines the
procedural sky, indexed/instanced bevelled terrain, fixtures, world text and
figures. Pass timers alone do not distinguish vertex, fragment, raster or
bandwidth limits; the draw ablations below isolate groups, not shader ISA.

For actual live-alpine, Luft's scene/shadow means are 17.52/0.48 ms at 720
and 24.31/0.47 ms at 1080. Old's unlabeled =pass-0= is the shadow pass and
=pass-1= is the scene, as confirmed in =luvcraft/render.lisp=: their means
are 7.11/7.69 ms at 720 and 7.30/9.47 ms at 1080. Old shadows therefore
consume a large part of that renderer's actual-world budget, unlike Luft's
simplified star-shadow patches. Bloom, shafts, panels and final presentation
are small GPU costs in these scenes, not the primary steady-state target.

** CPU preparation is not a steady-state frame cost

Settled live scenes do not remesh/repack every timed frame. Startup wrappers
measure inclusive wall times, including worker calls; parallel/nested totals
must not be added as exclusive CPU time. In the first live-alpine 720 setup,
16 chunk mesh calls total 22.40 ms, light-word packing 36.26 ms, population
preparation 52.89 ms (including packing), and upload/publication 313.75 ms.
The full setup is 19.82 seconds, so these wrappers do not explain the
majority of startup generation, capture, initialization and pipeline work.
For the default atelier, the same measured totals vary across the two
resolutions: meshing 14.25–23.42 ms, light packing 41.39–54.13 ms, population
preparation 56.75–73.47 ms, uploads 19.52–309.36 ms, total setup 9.45–10.97 s.
Do not turn those startup costs into per-frame claims or attribute their
variation to a particular subsystem without another controlled profile.

The later old live-alpine 720 setup records 169 halo gathers totaling
99.96 ms and 169 mesh calls totaling 305.96 ms. These are CPU preparation
records in the single-sample cohort, not extra GPU milliseconds.

A separate 1200-frame live-alpine 720 CPU sampling run at
[[https://github.com/mbrock/luv/commit/812b3fd][812b3fd]] collected 4325 samples at 1 ms. =encode-terrain= accounts for 48.3%
of cumulative CPU samples; the Vulkan indexed-draw encoder, nested within it,
accounts for 36.7%. CLOS dispatch/accessor/type checks are prominent, and
=arch_set_fp_modes= alone is 9.1% self samples (=arch_get_fp_modes= 1.1%).
The Vulkan driver environment masks/restores FP traps around individual
operations. Those percentages overlap and cannot be added into a speedup
claim. This profile wraps the measurement function, including warmup,
instrumentation, query collection and cleanup, not just production encoding.
Its timings are excluded from the baseline FPS table. The
[[https://github.com/mbrock/luv/blob/main/wiki/measurements/chapel-cpu-profile-2026-10-23.txt][flat sampling report]] retains the full attribution, including unknown/native frames.

In the first baseline repetition, 100 awake balls take 0.226/0.246 ms mean
simulation time on Luft/old at 720, versus 1.165/0.950 ms encoding. At 1080
the simulation means rise to 1.020/0.300 ms in that ordinary-session sample.
Turtle advancement is only 0.012–0.062 ms in those runs. The high total frame
tails should therefore not all be blamed on physics or lighting preparation.

** A discrete-GPU memory placement witness, not a proven bandwidth bottleneck

The Vulkan buffer allocator requests the first compatible host-visible,
host-coherent memory type for /every/ buffer. A real-device probe created
64 KiB vertex, index, storage and uniform buffers. All four have compatible
memory bits =0x7AD= and select memory type 2, flags
=(:host-visible :host-coherent)=, heap 1. This is /not/ device-local memory.
=vulkaninfo= confirms heap 1 lacks DEVICE_LOCAL; type 3 is a later
device-local/host-visible/coherent type in a 256 MiB heap, and the large
device-local heap is separate. Textures already prefer device-local memory.

Thus discrete-GPU mesh/star/index data currently use the upload-memory policy.
This is a strong reason to test device-local immutable buffers with staged
uploads before rewriting material shaders. It does /not/ prove how many
milliseconds are PCIe traffic: no bandwidth/occupancy counters or relocation
A/B were collected. Choosing the small mapped VRAM heap globally is not a
safe one-line fix; capacity, updates and lifetime still matter. The
[[https://github.com/mbrock/luv/blob/main/wiki/measurements/chapel-memory-2026-10-23.txt][memory probe and physical memory properties]] preserve the witness.

** NEXT Ranked experiments, not optimizations made here

1. Test device-local static vertex/index/star/material buffers and staged
   uploads on discrete Vulkan, retaining mapped buffers for suitable dynamic
   data. Measure the scene and old shadow passes again; verify capacity,
   lifetime and update correctness. Memory placement is established, its
   contribution to frame time is still a hypothesis.
2. Isolate the terrain vertex/material/fragment workload and visibility.
   Live-alpine 1080 falls from 26.14 to 1.94 ms GPU with terrain omitted;
   rich bevel/material/atmosphere shaders and repeated star draws deserve
   counters/disassembly before choosing ALU, geometry, culling or bandwidth
   work. Do not start with bloom/shafts.
3. Batch/specialize terrain indexed-draw encoding and investigate amortizing
   per-operation Vulkan FP-environment guards at a safe ownership boundary.
   Preserve validation and trap restoration; CPU sampling identifies this
   family, not a proven safe shortcut.
4. For old Luvcraft, simplify/cull shadow geometry or reuse suitable depth
   work: its live alpine shadow pass alone is about 7.1–7.3 ms, versus
   roughly 0.48 ms for Luft's simplified star casters.
5. Evaluate an explicitly quality-matched AA configuration and the native
   TAA-on path. The one-sample control saves GPU work, but changes quality
   and does not by itself explain the whole terrain cost. Investigate sky
   coverage/caching separately; the covered-cave result is architecture-
   dependent (temple's tile GPU showed no benefit from omitting covered sky).
6. Treat light packing/upload publication as edit/streaming latency work,
   not this settled-frame bottleneck. Profile the unaccounted startup work
   separately before claiming meshing dominates startup.

No production allocator, shader or render-pass optimization was made by
this experiment. The independently landed Metal creature pipeline-order fix
is included in the measured source and was required for correct rendering.

** Verification and remaining limits

=make= and =make test= pass after rebasing the benchmark capture change over
the other agents' focus/UI changes: 35 suites, 42 tasks. Strict Parinfer and
=git diff --check= pass. A separate check compares all 38 baseline wiki rows
against the 76 raw records and checks sample counts, extents and AA flags.
The live/atelier capture smoke passes with GPU samples and inspected images.
=scripts/wiki dangling= runs successfully but lists two pre-existing code
references, =TR4VLR= and =H1GHLD= in =captures/luft-portraits.lisp=; neither
was added here. The registered wiki page builds and its rendered ID, table
values and temple cross-reference are checked. The site build also warns
about pre-existing prose mentions =W9GQ3D=, =LSVW2S=, =UABDNH= and =CPIOH5=
in =mathematical-shaders.org=. There are no new unresolved IDs from this figure.

No connected-monitor run, frame-overlapped presentation throughput,
clock-locked tails, hardware shader counters, or default-TAA performance
claim is supplied. Cave lighting parity is explicitly unresolved. The
source cohorts are recorded rather than silently mixing later changes into
an already-running image.
